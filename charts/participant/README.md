# participant

Umbrella Helm chart that deploys a full Dataspace Ecosystem **participant**:

| Component                     | Chart                                    | Source                                         |
|-------------------------------|-------------------------------------------|-------------------------------------------------|
| Control Plane                 | `controlplane`                            | `../control-plane` (this repo)                  |
| Data Plane                    | `dataplane`                               | `../data-plane` (this repo)                     |
| Identity Hub                  | `identityhub`                             | `../identity-hub` (this repo)                   |
| Kafka Proxy K8s Manager        | `kafka-proxy`                             | `../kafka-proxy-k8s-manager` (this repo)        |
| Telemetry Agent               | `telemetryagent`                          | `../telemetry-agent` (this repo)                |

This mirrors the DSE component set deployed by the `terraform/backend/participant`
module in [`cloud-native-jdf/eonax-iac-workflows`](https://github.com/cloud-native-jdf/eonax-iac-workflows),
which is the reference automation used to deploy participants today. It does **not**
include the Content Definition Service ([`cr-bff`](https://github.com/amadeus-creation-platform/cr-bff)),
the "authority" components (`federated-catalog`, `federated-catalog-filter`,
`issuer-service`), or the shared "telemetry backend" components
(`telemetry-service`, `telemetry-storage`, `telemetry-csv-manager`,
`charts/telemetry/*`), which are deployed separately per that Terraform layout.

cr-bff publishes its own independently versioned Helm chart to a private OCI
registry (it is not vendored as a dependency here, since its Helm chart is
generated by `skube-parent` at `mvn package` and isn't committed to git). A
full participant deployment composes this chart together with cr-bff's chart
at the Argo CD layer — e.g. a multi-source `Application` referencing both
charts with independent `targetRevision`s — rather than nesting them into one
umbrella chart.

## Usage

```bash
# Vendor the local subcharts into charts/
helm dependency update ./charts/participant

# Install/upgrade one participant
helm upgrade --install <participant-name> ./charts/participant \
  -n <namespace> \
  -f my-participant-values.yaml
```

Set `dataplane.enabled`, `kafka-proxy.enabled`, or `telemetryagent.enabled`
to `false` in your values file to skip that component (all default to `true`).
Disabling `dataplane` also skips its OpenShift route (`global.route`). This
matches the optionality already present in the Terraform module.

## `global.*` values contract

Every subchart reads a shared `global` values block (Helm automatically
injects the umbrella chart's top-level `global` into each subchart's
context). Each chart derives its own release-name-based URLs, image
repository names, JDBC URLs, DID encoding, OTEL attributes, and vault config
blocks from these primitives — the same computations Terraform previously
performed in `terraform/backend/participant/*.tf`. This is the values
surface an external Argo CD values repository (pull model) needs to supply
per participant/environment; it does **not** need to replicate Terraform's
derivation logic.

```yaml
global:
  participantName: ""      # e.g. "acme" — used to derive release names,
                            # vault folder, vault token secret name, OTEL tenant_id
  environment: ""           # e.g. "dev" — used in OTEL deployment.environment
  useHttps: true
  db:
    serverFqdn: ""          # shared PostgreSQL server hostname
    name: ""                # shared database name
    credentials:
      secret:
        name: ""             # shared DB credentials secret name (Terraform's
                              # "<participantName>-db"); falls back to
                              # participantName-derived default when unset
  image:
    baseRepository: ""      # Terraform's `base_docker_image`
    namePrefix: ""           # Terraform's `image_name_prefix`
  vaultProvider: ""          # e.g. "hashicorp" or "azure"; mapped to the
                              # published hashicorpvault/azurevault image suffix
  keys:
    privateKeyAlias: ""      # shared private key vault alias (Terraform's
                              # "<participantName>-privatekey"), used by
                              # dataplane/identityhub/telemetryagent when unset
    publicKeyAlias: ""       # shared public key vault alias (Terraform's
                              # "<participantName>-publickey"), used by
                              # dataplane/identityhub when unset (telemetryagent's
                              # public key alias is derived from
                              # global.identityHub.didWebUrl instead)
  identityHub:
    didWebUrl: ""            # this participant's Identity Hub DID —
                              # shared as EDC_PARTICIPANT_ID by controlplane/
                              # dataplane/telemetryagent, and as identityhub's
                              # own DID when not set explicitly
  authority:
    didWebUrl: ""            # the dataspace authority's DID — DSE_AUTHORITY_DID
  vault:
    url: "https://vault:8200" # convenience default; only set at this (umbrella)
                               # level — do NOT duplicate a non-empty default in
                               # any subchart's own values.yaml (see Notes below)
  telemetry:
    enabled: false            # enables OTEL_RESOURCE_ATTRIBUTES on every component
```

Any subchart-specific value set explicitly (e.g. `controlplane.controlplane.postgresql.jdbcUrl`)
always takes precedence over what is derived from `global`. `global.db.credentials.secret.name`
and `global.keys.*` let you set the shared DB secret name / key aliases once
instead of repeating them per component — omit them entirely to fall back to
Terraform's participantName-derived naming convention. Fields that are still
irreducibly per-component (not derivable from `global`) — e.g. vault token
key names, image tags — remain plain Helm values under each component's own
section.

### Notes

- `global.vault.url`'s convenience non-empty default lives **only** in this
  umbrella chart. Every subchart's own `values.yaml` stub defaults
  `global.vault.url` to `""`, because a non-empty default there would make
  each subchart's Vault integration block always render, even for standalone
  installs that don't use Vault.
- `kafka-proxy` does not use `global.vaultProvider` in its image repository
  formula (Terraform doesn't suffix that component's image name with the
  vault provider), and derives its `participantId`/`vaultFolder`/
  `vaultTokenSecret.name` directly from `global.participantName`.

## Migrating an existing Terraform-deployed participant

Each component's Kubernetes `Deployment`/`Service` selector includes an
`app.kubernetes.io/instance` label derived from `.Release.Name`. Terraform
deploys each component as its **own** Helm release (e.g. `<participant>-controlplane`,
`<participant>-dataplane`), so under this umbrella chart — a single release
named `<participant>` shared by every component — that derived value changes.
Since Kubernetes selectors are immutable, an in-place `helm upgrade`/Argo CD
sync from the old standalone releases to this umbrella chart would fail and
require deleting/recreating every Deployment.

To avoid that, every component exposes an `instanceOverride` value
(`controlplane.controlplane.instanceOverride`, `dataplane.dataplane.instanceOverride`,
`identityhub.identityhub.instanceOverride`, `telemetryagent.telemetryagent.instanceOverride`,
`kafka-proxy.kafkaProxy.manager.instanceOverride`) that pins the selector to the
component's old Terraform release name during cutover:

```yaml
controlplane:
  controlplane:
    instanceOverride: "<participant>-controlplane"
dataplane:
  dataplane:
    instanceOverride: "<participant>-dataplane"
identityhub:
  identityhub:
    instanceOverride: "<participant>-identityhub"
telemetryagent:
  telemetryagent:
    instanceOverride: "<participant>-telemetryagent"
kafka-proxy:
  kafkaProxy:
    manager:
      instanceOverride: "<participant>-kafka-proxy"
```

For the data plane, the chart retains its historical `-dataplane` selector
suffix after applying `instanceOverride`. Therefore the documented
`<participant>-dataplane` override reproduces the old standalone selector
`<participant>-dataplane-dataplane`.

Leave these unset (the default) for brand-new participants — only existing,
already-running participants being migrated need them set.

## Control-plane ingress: reproducing the Terraform OpenShift route

Terraform provisions the control-plane's public ingress as a **separate**
`kubernetes_ingress_v1` resource (outside the Helm release, which sets
`ingress.enabled: false`) exposing two paths on one host, both pointing at
the control-plane Service on different ports, with OpenShift-route +
cert-manager annotations:

- `/api/management` → port `8181`
- `/api/dsp` → port `8282`
- `cert-manager.io/cluster-issuer: paas`
- `route.openshift.io/termination: reencrypt`
- `route.openshift.io/destination-ca-certificate-secret: <ca-secret>`

The chart's own `controlplane.ingress` template already supports multiple
endpoints and arbitrary annotations, so the same result is achieved purely
through values — no separate Terraform-managed resource needed:

```yaml
controlplane:
  controlplane:
    ingress:
      enabled: true
      hostname: "<participant>.<route-domain>"
      endpoints:
        - path: /api/management
          port: 8181
        - path: /api/dsp
          port: 8282
      certManager:
        clusterIssuer: paas
      annotations:
        route.openshift.io/termination: reencrypt
        route.openshift.io/destination-ca-certificate-secret: "<ca-secret>"
      tls:
        enabled: true
```

`tls.enabled: true` is required so the Ingress carries a `tls:` stanza at
all (OpenShift's Ingress-to-Route conversion only sets up TLS termination
when one is present); the generated `secretName` itself is not used for
`reencrypt` termination since OpenShift derives the destination CA from the
`route.openshift.io/destination-ca-certificate-secret` annotation instead.
